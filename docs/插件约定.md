# 插件约定：能力交给模型判断，兜底默认关闭

从 2026-10-27 起，本仓库的插件遵守这条约定。

## 原则

**能力注册成 `llm_tool`，用不用由模型自己决定。**

用户说「做个表情包」「给我点赞」「发条说说」时，由模型判断该不该调哪個工具，
而不是靠关键词正则抢先拦截 —— 后者会跳过模型的判断，还经常匹配不准
（比如「做**一个**表情包」匹配不到 `做(个|一)?表情`）。

## 硬性要求

1. **每个能主动做的事，必须有对应的 `llm_tool`**，并且在 docstring 里写清楚：
   什么时候用、参数含义、有什么后果。
2. **关键词兜底默认关闭**。保留 `@filter.regex` 的处理函数必须在开头判断：

   ```python
   if not _keyword_fallback_on():
       return
   ```

   需要临时恢复兜底时，建一个空文件：

   ```
   D:\AstrBot\bot\data\plugin_data\keyword_fallback.on
   ```

3. **兜底不得抢占**：不要 `stop_event()`，让消息继续流向 LLM。
4. **有实际后果的动作**（点赞、发说说、改昵称、换头像）必须：
   - 校验是不是主人（`_owner()`）
   - 有频率/每日上限，失败要退还额度
5. **模型看不到的副作用要记账**：发完说说、发完动态，把「我做了什么」写进
   对话历史或记忆，否则下一轮她会不认账。

## 提示词里要告诉她

`soul` 每轮注入一段「你能自己做的事」工具清单（见 `prompt_block`）。
新增能力时，记得把工具名加进那段清单。

## 为什么

- 关键词表永远列不全，还容易误伤（「今天好累」里没有关键词，但「画一张」误触）
- 模型拿到工具描述后，能结合上下文判断「现在该不该做」
- 兜底关掉后，行为可预期：她要么调用工具，要么直说做不到，不会假装答应
